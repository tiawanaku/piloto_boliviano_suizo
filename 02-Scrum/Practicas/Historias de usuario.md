# Historias de usuario

Volver a [[Scrum MOC]] · Plantilla: [[Plantilla Historia de usuario]]

Descripción breve de una funcionalidad **desde la perspectiva de quien la usa**.

## Formato
> **Como** [rol]
> **quiero** [acción / capacidad]
> **para** [beneficio / valor]

### Ejemplo del proyecto
> **Como** docente
> **quiero** iniciar sesión con mi correo institucional y contraseña
> **para** acceder a mis aulas virtuales sin depender de otra persona.

→ [[HU-001 Iniciar sesion con correo institucional]]

## Las 3 C
1. **Card (tarjeta):** la frase breve.
2. **Conversation (conversación):** el detalle surge hablando con el PO y usuarios.
3. **Confirmation (confirmación):** [[Criterios de aceptacion]].

## Épicas
Historias demasiado grandes para un sprint. Se dividen en el [[Refinamiento del backlog]]. En este vault viven en `03-Producto/Epicas`, p. ej. [[EP-01 Login plantel administrativo y docentes]].

## Calidad
Una buena historia cumple [[Criterios INVEST]].

## Historias técnicas / habilitadoras
A veces se necesita trabajo técnico (p. ej. configurar el servidor de correo). Redactarlo enfatizando el valor: *"Como soporte TI quiero que el sistema envíe correos desde el dominio institucional para que el personal confíe en los mensajes de recuperación."*
