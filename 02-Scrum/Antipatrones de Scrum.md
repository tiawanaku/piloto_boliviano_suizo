# Antipatrones de Scrum (qué evitar)

Volver a [[Scrum MOC]]

| Antipatrón | Síntoma | Corrección |
|---|---|---|
| Daily como reporte de estado | Cada persona informa al Scrum Master | La daily es *de los Developers* y para el [[Objetivo del sprint]] |
| PO ausente | Historias sin aclarar, decisiones demoradas | Acordar disponibilidad; proxy con autoridad |
| Sprint sin objetivo | "Hacer las historias 1 a 7" | Formular un [[Objetivo del sprint]] con valor |
| DoD flexible | "Está terminado, solo falta probar" | Respetar la [[Definicion de Terminado]] |
| Cambiar el alcance a mitad del sprint sin acuerdo | Trabajo nuevo entra cada día | Negociar con el PO; si el objetivo se vuelve obsoleto, cancelar el sprint |
| Retro sin acciones | Mismas quejas cada sprint | Máx. 1–3 acciones con responsable, incluidas en el siguiente [[Sprint Backlog]] |
| Historias técnicas sin valor | "Crear tabla usuarios" | Redactar desde el usuario: [[Historias de usuario]] |
| Review como demo de PowerPoint | Se muestran diapositivas | Mostrar software funcionando ([[Incremento]]) |
| Mini-cascada dentro del sprint | QA recibe todo el último día | Probar continuamente; swarming |
